## 目标和设计约束

优先修复可触发的内存边界和失败契约，随后加强门禁、减少重复执行。
维持现有组件所有权、单 executor、复制请求、latest-wins 完整帧和用户交互。
不借此重写 DOS DEBUG 命令、扩大文本/图形容量、改 Core、媒体格式或快照格式。
正常输入的输出须保持；错误输入明确失败，不能产生越界、假成功或静默漏记。

七项有限台账是本任务的收口范围。每项必须有实现证据、证明无需修改的理由，
或所有者批准的延期；不能用清单门禁通过代替动态语义证明。

### S2：Common 请求和队列通知失败（P2）

准入基线 `f4941481`。先冻结提交、唤醒、完成、退出四类路径及其数据所有权，
再给出具体方案、文件范围和代码增删预估；本次准入仅改治理文档，不把尚未
审计的失败处理方案当成可执行补丁。若需变更公开等待/取消契约，仍先报批。

- 源码：`src/common/session/control.c`、`src/common/machine/machine.c`。
- 证据：Session 入队/故障槽忽略 event signal 结果；Machine 请求提交忽略
  reset/signal，媒体、debug、快照完成通知也忽略 signal。底层失败时可能
  接受请求却未唤醒消费者，或让同步调用永久等待；尚未注入故障复现。
- 方案：先列出所有提交、唤醒、完成和退出调用点，区分“尚未接受”和
  “已经接受且可能正在执行”。处理返回值并复用已有终止、取消及请求收尾。
  若完成通知失败，不得直接让调用者释放 executor 仍借用的 payload/context。
  不使用轮询重试、第二事件通道或每个出口一套清理。
- 验证：分别注入 reset、提交 signal、完成 signal 故障；证明拒绝不执行、
  接受不重放、调用者不会无限等待、借用数据在 worker 退出前仍有效。
  保留已修复的 debugger 关闭/暂停销毁竞争测试。
- 设计检查点：若现有等待/取消契约无法安全表达通知失败，先报告最小接口
  方案及影响，取得该边界变更批准；不得用增加平行状态来隐瞒这个限制。

- 验证：填满、多来源、重复 make、拒绝后的来源退休；确认下游从未收到

### S6：xasm32 固定分派表精简

- 源码：`src/x86/xasm32/dasm32.c`。
- 证据：每次 `dasm32()` 清零新 context，再填入两个 256 项函数表，实例
  `initialized` 不会跨调用复用；这些 handler 映射本身不随解析状态改变。
- 方案：固定分派表改为文件内只读常量，删除 context 中的表及初始化标志。
  解析状态继续每次调用独立，不引入可变全局缓存；保持 handler 和原始输出。
- 验证：逐项核对全部 512 个映射；回归合法/非法 opcode、前缀和现有
  ModRM/SIB 遍历。报告实际栈占用、源码和只读数据变化，不预先承诺净减行数
  或运行加速。

### S7：Storage fill 合并刷新

- 源码：`src/lib/storage/medium.c`，必要的既有内部 file 操作。
- 证据：DIRECT 的 `fill_at()` 每 512 字节调用一次会 flush 的 `write_at()`；
  填充 1 MiB 对应 2048 次 flush。尚未测量实际性能收益。
- 方案：单次 fill 保留有界分块写入，在该操作结束前统一刷新；单次公开
  write 的既有语义保持。避免复制整套验证/写入实现，不增加公共 API。
  必须定义中途写失败时的刷新和错误优先级，不能仅把 flush 移到成功分支。
- 验证：空填充、跨页、尾页、DIRECT/READONLY/OVERLAY、写入和 flush 故障；
  通过调用计数证明减少刷新，成功返回时验证实际文件内容。错误路径仍明确
  报错，不声称提供事务回滚。无需长时间性能测量。

## 实施和退出标准

正式准入后按 S1--S7 串行执行。每个 S 开始前重新核对调用链，报告预计文件
和生产/测试新增、删除、净变化；完成后使用 Git diff 分别统计实际值，说明
保留路径及同类问题处置。S2 的通知失败方案须在修改前具体化。

每个代码 S 更新所属 manifest，执行针对性失败/边界测试、严格 C11 双宽度
构建及适用的后台回归，交付两份 package EXE；桌面测试采用已有隔离方案。
按项目 P 和实际变更复核规则提交推送，报告未覆盖平台，不将 Windows 通过
等同于 Linux 运行验收。用户 INI、磁盘、快照及主线程工作均不得被覆盖。

最终七项台账逐一闭环，六目录仍可按现有四/六组件组合独立复制构建；没有
新增平行 executor、输入账本、事件通道或可变解析全局状态。所有者验收后
才正式关闭未来准入的 T 任务。
