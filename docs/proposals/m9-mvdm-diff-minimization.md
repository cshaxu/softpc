# MVDM / OpenNT 差异审计与精简

## 请求、基线和边界

原始请求："帮我审计一下，mvdm当前和原始opennt代码镜像出现了多少处 & 多少行diff，都是为什么？"
后续要求："末尾空行请帮我处理干净，去掉diff；还有，所有diff里面不必要的diff，可以被干净处理掉的diff，列一下，看看怎么减少diff"。
本次准入："按照这个调研评估报告，设计T61的任务proposal和S任务拆解，写入proposal，并直接准入。"
持续目标：单人双角色执行，在保障系统正常运作和必要功能修复的前提下，减少与原始 OpenNT 的差异。

当前产品基线为已手测通过的 T60 3df951c；原始参考为只读
OpenNT 5e4619ab61c2aa76151e03973cce340be2933e61 的
nt/private/mvdm/softpc.new，同路径比较 src/mvdm/softpc.new。
外部树不是构建、运行或验收依赖；只读对照不修改外部树。
只恢复已导入同路径文件中的原始内容，保留原有来源/版权声明；不扩大选入文件、
固件或媒体范围，不形成新的许可证或发布主张。

目标不是减少当前源码行数，而是减少不必要的原始差异。保留必要 x64/C-VID
指针宽度修正、CPU/debug/HLT 接线、设备/FPU/绘制修复和 D6 BOP 兼容。
不得新增 overlay、机械替换构建脚本、第二实现、泛化适配框架或新产品语义。
Lib/Common、test/lib、test/common 及其 manifest 不修改；需要时先请求新授权。
App/VM 不做顺手重构；Compat/构建仅允许键盘/声音现有宿主边界的必要等价接线。
用户 INI、ROM、媒体不动。不得通过删功能、删原始文件或删测试来降低统计。

## 统计口径和收敛台账

S1 冻结实际 tracked 文件全集、两端 revision/hash、比较工具与参数。逐文件记录
同路径来源、字节相等、默认三行上下文 hunk 数、增加/删除行；另报行尾差异，
不以忽略空白的结果替代主统计。未选入文件单列，不算修改；若出现无来源文件
必须单列解释。区块数不是独立功能数。每个差异 hunk 都要落入一个原因/处置，
同类机械替换可以用明确模式覆盖，但必须列出例外，不能仅按目录猜原因。

处置只有：必要保留（原因/调用者/证据）、本任务恢复（阶段/前后证明）、
评估后保留（为何精简会增加复杂度或影响行为）、超界待用户裁决。
未知原因不得标为必要。总账按下列十二组互斥汇总并与逐文件数字对账：
C-VID 规则、其余 C-VID、CCPU、base/inc、BIOS、通信、键鼠、support、系统设备、
视频控制器、host 头、host 实现。新增发现必须有归组/处置，不能静默遗漏。

S1 的[当前差异账本](../etc/evidence/softpc/pristine-divergence-current.md)
记录冻结全集、两种统计口径、逐文件内容原因和处置。原 M1 清单已明确归档为
历史快照并互链，不并存两份“当前”权威。清单只记录事实与理由，不生成或改写构建源码。

所有阶段串行，前一 S 实施提交推送后切换审查角色核对实际 diff，合格才收口。

## 验证与交付

每个代码阶段使用现有 tests-x64/tests-x86 和串行 test-x64/test-x86 全量套件，
补产品 test/unit 的针对性等价证明，不改共享测试。保留 T60 的 IRQ、VGA
边界/dirty/pan、C-VID、x87 回归以及启动/暂停/恢复/重启、输入、包测试。
固定交付 assets/binary/softpc32.exe 与 softpc64.exe；不生成 *_s3.exe。
只读/文档阶段不为满足形式伪造构建，记录沿用的双宽度哈希。

每个完整 P 提交并推送 main；结束时核对远端与工作区。临时预处理/对照数据
只在 build 下使用，结束后清理自有临时目录，排除 build/output 及用户数据。
外部对照文件不成为 CTest 或正常构建的必需输入。每次关闭同时报告原始 diff
变化与项目自身生产/测试行数变化，禁止用净减少掩盖原始代码被大幅重写。
