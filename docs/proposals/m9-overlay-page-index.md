# Overlay 页索引优化

从 storage 性能 TODO 提升为候选；所有者现要求将本方案写入 proposal 并移至队首。

## 问题与设计约束

`src/lib/storage/medium.c` 当前每次查找 dirty page 都从链表头线性扫描。
单页查询 O(n)，大量不同 dirty page 的访问可能累计成平方级查找成本。
先用可重复的稀疏/密集、大量 dirty page 工作负载建立耗时和内存基线，
再选择最简单且有实际收益的页索引。不为理论复杂度引入通用容器框架。

保留现有公开 API、4 KiB 页覆盖行为、只读底层与内存 dirty 数据所有权。
不增加 commit 能力，不改变 direct/readonly 模式，不修改用户介质。

## 首选方案：按页号直接索引

磁盘容量在打开时已知。仅 OVERLAY 使用页指针数组，每个元素对应一个
4 KiB 页；元素数为容量除以 4096 后向上取整。空指针表示未修改，继续读
底层文件；首次写入分配页并读入原内容，成功后才安装指针。后续访问直接
按页号索引。无底层文件的 zero overlay 保留原有补零语义。

数组成为页的唯一所有者，删除页节点的 `index`、`next` 和链表查找；不保留
第二套链表或索引。销毁时释放非空页及数组。公开 API、独占 lease 和已有
跨页写入失败语义均不变，不增加事务、线程或通用容器框架。

页数计算不能使用可能溢出的“容量 + 4095”；数组字节数也须校验乘法边界。
零容量保持合法且不依赖零字节分配结果。分配/原页读取失败不得安装半成品
页或破坏已有内容；创建失败清理、尾页及销毁仍沿现有唯一生命周期处理。

### 内存与性能取舍

查询由 O(修改页数) 变为 O(1)，但数组内存与介质总容量有关，初始化/销毁
需要遍历数组。数据页仍按需分配，并非在内存中复制整个磁盘。

| 介质容量 | x64 指针数组 | x86 指针数组 |
| --- | --- | --- |
| 504 MiB | 1008 KiB | 504 KiB |
| 2 GiB | 4 MiB | 2 MiB |
| 1 TiB | 2 GiB | 1 GiB |

以上仅为指针数组，不含数据页与分配器开销。不能因为当前 SoftPC 使用小盘，
就静默缩小共享 Lib 的可用容量范围。实施前比较小盘、大量修改页和大型稀疏
介质的时间与内存成本；若直接数组代价不合适，先汇报证据，再评审两级按需
页表。两级页表是备选，不与直接数组同时维护成两个运行策略，也不默认引入
哈希表、平衡树或动态策略切换。

## 组件范围与快照兼容性

生产修改仅在 `src/lib/storage/medium.c`，如无新证据，不改公共头文件、
Common、Core、App 或 x86。测试主要在 `test/lib`，产品快照回归可以补充
必要测试，但不改其编码实现。

已核对 `src/core/compat/media_snapshot.c`：保存通过
`lib_storage_medium_read_at()` 按偏移扫描、比较原始和有效内容，编码介质
元数据及差异块的偏移、长度、数据；加载通过 `lib_storage_medium_write_at()`
重放。它不序列化 Storage 内部链表、指针或节点结构。

因此只换内部索引不会改变快照字段、差异块顺序或跨 x86/x64 格式，不需要
新版本号、转换器或旧格式兼容分支。同一基础介质和有效内容必须得到逐字节
相同的快照介质段。完整磁盘扫描及 SHA 计算仍存在；本优化只消除扫描时的
链表查找成本，不承诺消除 I/O 或哈希成本。

## 拟议实施拆分

1. S1：冻结当前 Storage 行为及快照介质段基线，建立可重复负载，测量链表
   成本并核定直接索引的内存代价；报告确切文件和代码增减估计。
2. S2：在 Storage 内替换唯一页索引，删除旧节点/遍历机制，补齐正常及失败
   测试。若 S1 不支持首选方案，先提交修订设计，不静默扩张实现。
3. S3：完成旧快照加载、介质段编码一致性、双宽度往返及产品回归；汇报实际
   性能、内存和逐组件增删行数，交付双 EXE，等待所有者验收后收口 T。

每个实施 S 开始前报告方案、文件范围和预估增删；完成后报告实际增加、删除、
净变化及构建测试结果，提交推送完整交付。不得将文档登记视为实施已准入。

## 实施验收

测试同页重复读写、跨页和尾页、稀疏覆盖、未修改页读取、分配失败及销毁。
同时覆盖零容量、索引容量计算边界、原页读取失败、zero overlay，以及
direct/readonly 不分配 overlay 索引且行为不变。
优化前后数据结果一致；同时报告小负载回归、大负载收益和额外内存。
对相同介质状态比较优化前后快照介质段字节，并验证旧快照加载、软硬盘
overlay 恢复及 x86/x64 往返；用隔离的小型测试介质，不污染 assets。
没有有用收益时应提交测量结论而非强行替换算法。
实施后按修改范围构建双宽度 EXE、执行共享库和产品回归并提交推送。
