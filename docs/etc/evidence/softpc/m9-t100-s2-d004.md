# T100 S2 D004 investigation

Owner authorizes investigation, not production implementation. Baseline is
720dfc60. No production, permanent test, binary, guest or user asset changed.
L001 and D001-D003 are owner-declined for this round; retain their evidence.

## Hardware contract and corrected finding

Primary references:
- [IBM VGA/XGA Technical Reference](https://www.ardent-tool.com/video/IBM_VGA_XGA_Technical_Reference_Manual_May92.pdf),
  printed pages 2-51, 2-54 and 2-85: enable all maps for chain4; low address
  bits select the map; write mode2 expands input bit n into map n.
- [Video Seven V7VGA Technical Reference](https://www.dosdays.co.uk/media/video_seven/v7_vga_techref.pdf),
  printed pages 3-26 and 3-71: chain4 selects the plane for both reads and
  writes, additionally gated by the plane mask; mode2 expands bits 0-3 into
  planes 0-3. No mode0-only exception is stated for this selection.

These are vendor documentation, not another emulator's implementation.
The V7 PDF exceeded the browser open limit; its indexed register sections
were read via search. IBM PDF sections were opened directly. No manual or
external source is imported into the repository.

The prior D004 description was too narrow: BYTE writes also fail. The original
mode2 lookup produces four plane bytes and applies existing logic/masking.
CHAIN4 memory stores then always extract REGBYTE (the lowest byte here),
even when address bits select planes 1-3. The address and enable checks are
correct; the final value belongs to the wrong plane. BYTE and WORD agreeing
with each other is therefore not proof of correctness.

Affected scalar families checked: sevid024 S2877-S2880 and sevid025 S2893-S2896.
The real port selector chooses these families. c_sas_storew reaches the normal
video write vector; c_sas_storedw uses the existing WORD path twice and inherits
the defect. This is not limited to an unused generated DWORD/bulk entry.

## Fresh dual-width actual-body evidence

Task-local copy of existing vga_frame_smoke initializes the real Machine and
BIOS mode13, then uses actual Sequencer/Graphics Controller ports. Initial
SR2=0f, SR4=0e, GR3=00, GR8=ff, GR5=42 yields chain=2, mode=2, state=1,
rotate=0, dither=0. No forced selector or copied device implementation.

Three routes: two BYTE glue calls, one WORD glue call, and c_sas_storew.
Independent expected bytes follow the vendor bit-to-plane mapping. Untouched
neighbor bytes are asserted. Baseline matrices cover all 256 byte values and
four starting-address residues, in mode0 and mode2. An additional mode2
matrix covers masks 7/15, replace/AND/OR/XOR, bit masks ff/0f, all residues
and 16 low-nibble values, using actual reads to load unequal plane latches
12/34/56/78. Actual selected states cover 0-15 (all four mode2 variants).

| Matrix, each architecture | Unchanged production | Isolated candidate |
| --- | --- | --- |
| Mode0, 3072 route cases | 3072 correct | 3072 correct |
| Mode2, 3072 route cases | 1920 mismatches | 3072 correct |
| Extended mode2, 3072 route cases | 2424 mismatches | 3072 correct |

x86 and x64 match. Each completed executable also runs the existing VGA
fixture assertions. Explicit CCPU WORD 0201 produces ff 00 before and ff ff
after; DWORD 08040201 produces ff 00 00 00 before and ff ff ff ff after.
An initial 64-vector subset reproduced the same class on both widths.
Probe setup failures were corrected: link-object slash normalization, a missing
local DWORD declaration and an initially incorrect byte-read return declaration.
Those failed setup attempts are not runtime evidence. Final compiles/links/runs
all exit zero; the diagnostic intentionally reports baseline mismatch counts
rather than pretending zero process exit means baseline pixel correctness.

## Minimal candidate and proof limits

Only task-owned copies change the final store to select the addressed byte:

    (IU8)(expanded >> ((destination_offset & 3) * 8))

The candidate uses the existing expanded IU32 local and existing r22 destination
offset at each store. It leaves expansion, logical operations, latches, masking,
addressing and dirty markers untouched. Four BYTE stores plus eight WORD stores:
sevid024 +4/-4, sevid025 +8/-8, total +12/-12, net zero source lines and 24
added-plus-deleted candidate mirror diff lines. No helper, branch, alternate
write path or new state. Temporary objects replace those two archive members
only for diagnostic linking; no transformed source enters the shipped build.

This proves the scalar defect and a bounded correction. It is not physical-card
measurement, a recorded DOS/Win3.1/Win95 incident, full hardware conformance,
or proof of every bulk/move/dither/rotate path. Ordinary mode13 mode0 writes
pass the control; observed user frequency is unknown. Permanent regression
and full qualification remain required if implementation is approved.

Actual source/candidate diff review confirms exactly twelve replacements and
unchanged baseline production. Documentation and pending decisions are the only
tracked changes. Owned workers terminate before scratch removal; reusable
Ninja/ccache trees and published artifacts remain unchanged.
