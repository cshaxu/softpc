## Hardware contract and corrected finding

Primary references:
- [IBM VGA/XGA Technical Reference](https://www.ardent-tool.com/video/IBM_VGA_XGA_Technical_Reference_Manual_May92.pdf),
  printed pages 2-51, 2-54 and 2-85: enable all maps for chain4; low address
  bits select the map; write mode2 expands input bit n into map n.
- [Video Seven V7VGA Technical Reference](https://www.dosdays.co.uk/media/video_seven/v7_vga_techref.pdf),
  printed pages 3-26 and 3-71: chain4 selects the plane for both reads and
  writes, additionally gated by the plane mask; mode2 expands bits 0-3 into
  planes 0-3. No mode0-only exception is stated for this selection.

These are vendor documentation, not another emulator's implementation.
The V7 PDF exceeded the browser open limit; its indexed register sections
were read via search. IBM PDF sections were opened directly. No manual or
external source is imported into the repository.

The prior D004 description was too narrow: BYTE writes also fail. The original
mode2 lookup produces four plane bytes and applies existing logic/masking.
CHAIN4 memory stores then always extract REGBYTE (the lowest byte here),
even when address bits select planes 1-3. The address and enable checks are
correct; the final value belongs to the wrong plane. BYTE and WORD agreeing
with each other is therefore not proof of correctness.

Affected scalar families checked: sevid024 S2877-S2880 and sevid025 S2893-S2896.
The real port selector chooses these families. c_sas_storew reaches the normal
video write vector; c_sas_storedw uses the existing WORD path twice and inherits
the defect. This is not limited to an unused generated DWORD/bulk entry.

## Minimal candidate and proof limits

Only task-owned copies change the final store to select the addressed byte:

    (IU8)(expanded >> ((destination_offset & 3) * 8))

The candidate uses the existing expanded IU32 local and existing r22 destination
offset at each store. It leaves expansion, logical operations, latches, masking,
addressing and dirty markers untouched. Four BYTE stores plus eight WORD stores:
sevid024 +4/-4, sevid025 +8/-8, total +12/-12, net zero source lines and 24
added-plus-deleted candidate patch lines against the local baseline (P4 below
corrects the earlier interpretation as additional XP diff). No helper, branch, alternate
write path or new state. Temporary objects replace those two archive members
only for diagnostic linking; no transformed source enters the shipped build.

This proves the scalar defect and a bounded correction. It is not physical-card
measurement, a recorded DOS/Win3.1/Win95 incident, full hardware conformance,
or proof of every bulk/move/dither/rotate path. Ordinary mode13 mode0 writes
pass the control; observed user frequency is unknown. Permanent regression
and full qualification remain required if implementation is approved.

Actual source/candidate diff review confirms exactly twelve replacements and
unchanged baseline production. Documentation and pending decisions are the only
tracked changes. Owned workers terminate before scratch removal; reusable
Ninja/ccache trees and published artifacts remain unchanged.

## P4 owner-approved implementation

Owner approves the demonstrated twelve-store correction and the normal cached
dual-width build/publication/full-test/commit/push delivery. The implementation
baseline is d7e38d32. Four BYTE stores in sevid024 and eight WORD stores in
sevid025 change only their final extraction expression. There is no public ABI,
snapshot format, bulk-path activation, fallback, helper or new state.

Permanent coverage extends the existing vga_frame_smoke by 52 lines. Actual
BIOS/ports select CHAIN4 mode2; masks 7/15, four logical operations, bit masks
ff/0f, four start residues and sixteen values exercise BYTE and actual CCPU
WORD/DWORD writes (3072 combinations per architecture). Payload bytes differ
within each WORD/DWORD. Actual reads load distinct plane latches; an independent
bit-to-plane oracle checks all written bytes, disabled planes and untouched
neighbors. No diagnostic-only production API or new test executable is added.

Same-test negative controls link the pre-fix sevid024 OR sevid025 body, separately,
before the unchanged machine archive. Both widths detect both omissions:
x86 assertion exit 0xc0000409; x64 assertion exit 3. Corrected focused VGA tests
pass on both widths. Previous P3's mode0 and broader byte-value controls remain
investigation evidence, not a claim that those extra matrices were added to the
permanent test or that a customer guest incident was reproduced.

The initial x86 build failed because the new helper preceded an existing local
c_sas_storew declaration. Adding its matching local declaration resolves the
fixture build; no production API changes. A direct manifest check also caught
raw CRLF hashes instead of the required normalized-LF hashes; only those two
local hash fields were corrected before full regression. Fixed XP/subset hashes
and CRLF mirror bodies are preserved. These setup failures are not test passes.

Actual production count is +12/-12 (net zero); tests +52/-0. Reproduce with
`git diff --numstat d7e38d32 -- src test`. The twelve approved replacements
are 24 added-plus-deleted local patch lines, NOT an increase of 24 in the
existing XP-relative diff. P4 verifies pinned XP bytes/hashes and runs
normalized-LF git diff --no-index --numstat against pre-P4 and final bodies:
sevid024 remains +488/-487; sevid025 remains +667/-666. Combined XP-relative
added/deleted total stays 2308 lines, delta zero. These stores already differed
from XP due to GDP ABI mapping; P4 adds semantic corrections on the same lines.

Similar-issue review enumerated mode2 scalar BYTE/WORD cases using
`case S_*_Chain4(Byte|Word)Write_00000002_*` in sevid024/sevid025: four cases
in each file, respectively one/two final stores, all twelve corrected. The
r22 value at each store is the existing destination offset; its low two bits
select shifts 0/8/16/24. Existing expansion, latch logic, masks and marker calls
